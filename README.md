# Odor Prediction Models
**Aroma contribution (classification) + Odor threshold (regression)**

This repository provides end‑to‑end, **train‑it‑yourself** pipelines for:
1) **Aroma contribution** from structure (multiclass + binary).
2) **Odor threshold (ODT)** regression predicting `-log10(ODT)` and `ODT (mg/L)`.

> 🔎 **No pre‑trained models or evaluation artifacts are shipped.**  
> You run the training locally and generate results under `outputs/`.

---

## ✨ What you get
- Reproducible training scripts (scaffold split, HPO, CV reports).
- Validation utilities that export vector figures (SVG/PDF) & per‑class tables.
- Lightweight GUI/CLI apps for inference (binary contribution & ODT).
- Minimal, dependency‑light design (RDKit via conda; everything else via pip).

## 🧾 Data formats

### 1) Multiclass classification (`data/merged_classified_multi.csv`)
Required columns (minimum):
- `SMILES` : canonical SMILES string
- `Major_Category` : normalized aroma category label (e.g., `Fruity`, `Floral`, `Green/Herbal`, …)

Example (CSV):
```csv
SMILES,Major_Category
CCO,Fruity
CC(C)O,Floral
```

### 2) Binary contribution (`data/merged_classified_binary.csv`)
Required columns:
- `SMILES`
- `Contribution` : binary label (`pos`/`neg` or `1`/`0`)

```csv
SMILES,Contribution
CCO,pos
CC(C)O,neg
```

### 3) ODT regression (`data/threshold_data.csv`)
Required columns:
- `SMILES`
- `threshold` : positive numeric value; training target is `-log10(threshold)`

```csv
SMILES,threshold
CCO,2.50
CC(C)O,0.84
```

> If you only have **names**, use `src/flavor/name_to_smiles.py` to resolve **Name → SMILES** (via PubChem).

## 🚀 Train & evaluate

### A) Multiclass classification — train
```bash
python src/flavor/train_flavor_models.py   --csv data/merged_classified_multi.csv   --outdir outputs/model_out_all   --val_size 0.20   --seed 42   --fingerprints ECFP4,ECFP6,MACCS   --nbits 1024   --models rf,gbdt,mlp   --tune random --n_iter 30   --cv_folds 5   --cv_group_scaffold   --imbalance_strategy class_weight
```
What happens:
- Canonical‑SMILES dedup; Murcko scaffold split (train/val).
- Feature build (ECFP4/6, MACCS + basic phys‑chem).
- HPO on train (`RandomizedSearchCV`, 5‑fold); final eval on val.
- Artifacts saved under `outputs/model_out_all/`:
  - per‑combo CV reports (mean ± std), vector confusion matrices (counts & normalized, SVG/PDF),
  - per‑class metrics tables, selected best model summaries, and logs.

> To include the GCN baseline, add `gcn` to `--models` (requires PyTorch + PyG).

### B) Validate saved models / combos
```bash
# Use the recorded validation split inside outdir
python src/flavor/validate_models.py   --outdir outputs/model_out_all   --only MACCS-RF   --subset val

# Evaluate multiple combos
python src/flavor/validate_models.py   --outdir outputs/model_out_all   --only MACCS-RF,ECFP4-MLP,ECFP6-GBDT   --subset auto

# Evaluate on a custom CSV (not the recorded split)
python src/flavor/validate_models.py   --csv data/merged_classified_multi.csv   --outdir outputs/model_out_all   --only ECFP6-GBDT   --subset all
```
`--subset` options:
- `auto` : prefer `outdir/val.csv` if present, otherwise `--csv`
- `val`  : force `outdir/val.csv`
- `train`: force `outdir/train.csv`
- `all`  : use `--csv` exactly as provided

### C) Binary contribution — quick GUI/CLI
```bash
# GUI (no text arguments → GUI shows)
python src/flavor/app_predict_gui.py --model outputs/model_out_binary_all/best_model.joblib

# CLI by SMILES
python src/flavor/app_predict_gui.py --model outputs/model_out_binary_all/best_model.joblib --smiles "CCO"

# CLI by name (requires pubchempy)
python src/flavor/app_predict_gui.py --model outputs/model_out_binary_all/best_model.joblib --name "linalool"
```

### D) ODT regression — train
```bash
python src/threshold/train_threshold_odt.py   --csv data/threshold_data.csv   --outdir outputs/model_out_threshold   --val_size 0.20   --seed 42   --fingerprints ECFP4,ECFP6,MACCS   --nbits 1024   --models rf,gbdt,mlp   --tune random --n_iter 30   --cv_folds 5   --cv_group_scaffold
```
Exports in `outputs/model_out_threshold/` include:
- `performance_summary_val.csv` (R²/RMSE per FP×Model)
- CV reports (fold‑wise and summary), validation predictions/metrics,
- band‑wise evaluation across tertiles,
- `best_model.joblib` + a JSON summary (feature list/order, model meta).

### E) ODT regression — predict
```bash
# CLI with SMILES; training unit mg/L
python src/threshold/predict_threshold.py   --model outputs/model_out_threshold/best_model.joblib   --smiles "CCO"   --train_unit mgL

# Show packaged model metadata
python src/threshold/predict_threshold.py   --model outputs/model_out_threshold/best_model.joblib   --show_info
```
If neither `--smiles` nor `--name` is given, a small GUI pops up.

## 📌 Tips
- For imbalanced categories, prefer `--imbalance_strategy class_weight`; oversampling is optional.
- Use vector exports (SVG/PDF) from validation for publication‑ready figures.
- Do **not** commit `outputs/` to Git; consider archiving final artifacts on Zenodo and citing DOI in papers.
